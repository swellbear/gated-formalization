# Training Ladder

**Standing onboarding path** for Gated Formalization operators.  
**Canonical rule:** `.cursor/rules/applications-gated-method.mdc` (Training Ladder section).  
**Checklist:** `workflow.md`.

**Purpose:** Move from undeniable, well-posed claims outward to mixed/high-Amb claims.  
**Difficulty axis:** well-posed → under-specified, and descriptive → elevated — **not** only objective → subjective.

**This file is documentation only.** Creating or running training applications requires separate authorization.

## Sequencing (certification)

- Stage **N** is **not** run for certification until stages **0–(N−1)** have closed **`SHARE_PACK.md`** files.
- Practice drafts outside sequence are allowed if labeled non-certifying; they do not unlock Stage N.
- Optional modes (**QI**, **CX**, **UX**, **CR**) only when the stage pass criterion calls for them **or** the operator authorizes.

---

## Fixed stages

| Stage | Name | Claim shape | Pass criterion |
|-------|------|-------------|----------------|
| **0** | Smoke / tautology | Definitional identity | Admissible; Amb ≈ 0; full closeout hygiene |
| **1** | Simple descriptive fact | Public, low-dispute fact | Admissible or Stable Provisional with clear anchors |
| **2** | Descriptive + scope lock | Fact restricted by time/place/population | Locks used correctly; no silent universalizing |
| **3** | Numerical standard (pass) | Metric with clean public data expected to clear | Bar established under evidence rubric |
| **4** | Numerical standard (fail) | Metric expected to fail or partially fail | Not-established honest; optional QI; no upgrade to “should” |
| **5** | Core + soft “should” | Descriptive core + mild recommendation | Claim-type split; “should” not forced |
| **6** | Uniqueness / preferability | “Alone / only / therefore preferable” | Forced-deviation handling; revision optional |
| **7** | Forecast / this-period extension | Historical pattern → “do it now” | Path vs prediction; UX optional |
| **8** | Contested mixed theory | Foundations / design / policy mix | Full residual menu; no false clearance |

---

## Pass hygiene (every stage)

Same as any application: dissertation / executive brief / **SHARE_PACK** / STATUS (**endpoint** vs **hard stop**) / Layers 1–3 as applicable / residual-branch menu when residuals remain / **Live vs stand-in** when prints or proxies are used.

**Endpoint** = examination done. **Hard stop** = endpoint + hygiene. Training credit for sequencing uses **closed SHARE_PACK** (sharing closure), not a skipped checklist.

---

## Operator reply grammar (training)

Same as standing method: `lock Rank N` · `authorize branch R-…` · `decline residual menu` · `run UX` / `decline UX` · `run QI` / `run CX` / `run CR` · `endpoint only` · `closeout` / `hard stop`.

## Learning loop

How the ladder relates to ongoing method improvement (not a substitute for live apps):

| Layer | Role |
|-------|------|
| **Ladder** | Fixtures / onboarding / pass–fail baseline |
| **Live apps** | Stress patterns |
| **Pattern map** (`TRACKER_PATTERN_MAP.md`) | Recurring tags |
| **Calibration log** (`logs/calibration_log.md`, ≥3 apps) | Deliberate method keep / tighten / loosen (**live apps only** by default; training fixtures excluded unless entry marked **training-only**) |
| **Standing rule updates** (`.cursor/rules/applications-gated-method.mdc`) | Actual method learning |

The ladder does **not** auto-rewrite the standing rule. Learning moves through observed patterns → calibration (≥3 closed apps) → explicit rule/template change when decided.
