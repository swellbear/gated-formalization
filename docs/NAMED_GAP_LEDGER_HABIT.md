# Keep one line per open gap so invents point at a real missing piece

A short working habit. It does not change how claims are scored.

## The habit

Every open fog gets **one line** on a named-gap ledger. This is a problem-solving scoreboard, not a horse-count.

Each line, in everyday words:

- **what’s missing** → **what would count as kill vs harden** → **last check** → **status**
- Status is one of: `open` / `killed` / `hardened` / `wrong-piece` / `restated` / `paused`

Invents that do not point at a ledger line **do not run**. Name the gap first.

**Wrong-piece** counts as progress. You learned that wasn’t the right fog. Then pick the next piece.

Two **restates** on the same gap → **pause** that string. Restating the same still-foggy result is not a new solve step.

Tiny practice or training runs can stay light.

## No fake clears

The **Operator** admits, rejects, or parks. Lab invents and tests. Lab never admits its own candidate.

A cheaper question is not a cleared claim. Lower Ambiguity is not clearance. Burned classes stay burned. This habit does not rewrite the admit rules. It does **not** authorize invent. Lab stays held unless a live string is already allowed.

## Why

Honesty and naming Ambiguity are not enough if invents wander off the named fog. A one-line ledger keeps every invent pointed at a real gap.

## Example line (not a skill claim)

This is only a picture of how a ledger line looks. It is **not** a skill claim. It is **not** skill-met. It is **not** elevated. It is **not** a null-burn.

`Brent month-of-year continuation (H-SPOT-MOY-CONT) year/vehicle fragility` → kill vs harden: a cheap check that would drop the horse vs only tighten the year/vehicle fog → last check: P4 year-stability → status: **paused**

Gloss: scoped + FRAGILE; year-stability HARDENED (P4); invent paused. Residual is still year/vehicle fragility — not a cleared skill.
